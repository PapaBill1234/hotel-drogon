Phase 5: the credits surface in React — purse and transaction ledger

Two legacy pages, both read-first:

- credits.php's #purse-habblet read $user->user("credits") — the live PolarIS
  row, not the ledger. /api/account/purse reads the same source, because a
  balance summed from phpretro_transactions would disagree with the hotel the
  moment the emulator changed credits itself.
- history.php read its own phpretro_transactions rows: created_at DESC, id DESC,
  LIMIT 100, rendered Date/Type/Amount/Balance/Description with the legacy date
  format and empty-state sentence. That is now TransactionService + the ledger
  table, shaped column-for-column from migrations/001_custom_tables.sql —
  including reference_id NULL and the idx_user_id_created index name — because
  the legacy writers still insert into this table.

Neither route takes a user id: the subject is always the session's user, so
another account's balance or ledger is unreachable rather than merely checked.

Neither ledger writer is ported yet (housekeeping credit adjustment is Phase 9,
the MyHabbo Homes store is Phase 8), so an empty history is the correct answer on
a stack this code alone produced. The browser suite proves the populated path by
installing two rows in exactly the legacy writers' shapes, asserting the
ordering, the negative amount, the date format and the empty state, then removing
them in a finally.

Voucher redemption stays absent: the plan makes it an explicit handoff, and a
disabled control with no handler is what the plan forbids.
