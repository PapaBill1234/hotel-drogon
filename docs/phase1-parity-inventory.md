### Schema correction carried by this unit

`users.auth_ticket` was declared `VARCHAR(255)` in `src/main.cpp`; PolarIS declares `varchar(256)`, and the legacy site wrote a 36-character ticket there. It is now `VARCHAR(256)`. `auth_ticket_expires_at` was **removed**: PolarIS has no such column, so the write in `UserAccountService::generateAuthTicket` would have failed against a real PolarIS database. That method had no callers, so nothing depended on it.

**A database created before this change keeps both old columns** — `CREATE TABLE IF NOT EXISTS` will not alter an existing table. Migrating one is:

```sql
ALTER TABLE users MODIFY auth_ticket VARCHAR(256) DEFAULT '';
ALTER TABLE users DROP COLUMN auth_ticket_expires_at;
```

Both statements are recorded here rather than run automatically: the plan requires a verified reason before a PolarIS-owned table is altered, and an automatic DDL migration is a bigger decision than this work unit should take on its own.
